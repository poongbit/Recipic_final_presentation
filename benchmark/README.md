# 분류 모델 재평가와 경량화 (2026.11)

졸업 프로젝트(2024) 이후 진행한 후속 작업입니다. 분류 모델의 정확도 92.9%가 믿을 만한 숫자인지 다시 확인하고, 모델을 줄였습니다.

> Google Colab에서 진행했습니다. 새 모델은 아직 앱에 연동하지 않았습니다.

## 요약

| 모델 | 크기 | 원본 테스트 777장 | 불량 제외 633장 | 생재료만 419장 |
|---|---|---|---|---|
| 기존: EfficientNet-Lite4, 분류층만 학습 (FP32) | 46.8MB | 80.7% | 85.2% | 92.6% |
| 신규: EfficientNet-Lite0 미세조정 (FP32) | 13.6MB | 87.5% | 90.2% | 93.3% |
| **신규: EfficientNet-Lite0 미세조정 (INT8)** | **4.1MB** | **87.9%** | **90.2%** | **93.6%** |

- 생재료 기준 정확도를 유지하면서(92.6% → 93.6%) 모델 크기를 46.8MB에서 4.1MB로 줄였습니다.
- 썰거나 익힌 재료까지 포함하면 85.2%에서 90.2%로 올랐습니다.
- CPU 지연 시간은 Colab x86 CPU 1스레드 기준 약 103ms에서 약 15ms입니다. 서로 다른 세션에서 잰 값이고 스마트폰 실측값이 아닙니다.

## 1. 기존 평가의 문제

졸업 프로젝트의 정확도 92.9%는 학습 데이터 843장을 무작위로 나눈 테스트 84장 기준이었습니다. 다시 확인해 보니 다음 문제가 있었습니다.

- 학습 데이터 843장 중 56장이 서로 같은 파일이었습니다. 무작위 분할이라 같은 사진이 학습과 테스트에 함께 들어갔을 수 있습니다.
- 데이터의 출처인 Kaggle 데이터셋의 공식 test 폴더는 10종 99장 중 90장이 학습 데이터와 같은 파일이었습니다. 독립된 테스트로 쓸 수 없었습니다.

## 2. 독립 테스트셋

Open Images V7의 검증·테스트 분할에서 777장을 모았습니다. Kaggle 데이터와 출처가 다르고 학습에 쓰지 않은 사진입니다.

- 사과, 바나나, 당근, 오이, 레몬, 감자, 토마토: 사람이 그린 경계 상자로 물체를 잘라낸 사진
- 옥수수, 마늘, 양파: 경계 상자가 없어 사진 전체에 붙은 라벨을 사용
- 목록: [`data/indep_test_v1_manifest.csv`](data/indep_test_v1_manifest.csv) (이미지 ID와 상자 좌표)

## 3. 테스트셋 전수 검수

777장을 모두 눈으로 확인해 세 가지로 나눴습니다. 판정은 [`data/test_audit_v1.csv`](data/test_audit_v1.csv)에 있습니다.

| 판정 | 장수 | 기준 |
|---|---|---|
| 생재료 | 419 | 통째의 생재료가 주 대상으로 보임 |
| 절단·조리 | 214 | 재료는 맞지만 썰거나, 익히거나, 절였거나, 덜 익은 상태 |
| 불량 | 144 | 라벨이 틀림, 대상이 안 보임, 여러 재료가 섞인 요리, 식별 불가 |

불량이 많았던 클래스와 원인은 다음과 같습니다.

- 레몬 43장: 라임과 오렌지가 레몬으로 라벨됨
- 양파 44장: 요리 사진, 밤, 무화과
- 오이 23장: 애호박이 오이로 라벨됨
- 옥수수 19장: 옥수수밭, 해산물 요리

## 4. 재학습

| 실험 | 학습 데이터 | 원본 테스트 777장 |
|---|---|---|
| 기존 Lite4 (분류층만 학습) | Kaggle 843장 | 80.7% |
| A. Lite0 미세조정 | Kaggle 787장 (중복 제거) | 65.6% |
| B. Lite0 미세조정 | Kaggle 787장 + Open Images 학습 분할 2,542장 | 87.3% |
| C. Lite0 미세조정 | Kaggle 787장 + Open Images 학습 분할 4,167장 | 87.5% |
| MobileNetV4-Conv-Medium 미세조정 | C와 같음 | 84.6% (INT8 65.8%) |

- A는 Kaggle 검증 정확도가 91.5%였지만 독립 테스트에서는 65.6%였습니다. 학습 방법만 바꿔서는 나아지지 않았고, 실제 사진을 추가했을 때 올랐습니다.
- 학습 데이터와 테스트셋의 이미지 ID가 겹치지 않는 것을 확인했습니다.
- MobileNetV4는 더 크고 느린데 정확도가 낮았고, INT8 양자화에서 정확도가 크게 떨어져 채택하지 않았습니다.
- 학습 설정: AdamW, 학습률 5e-4, OneCycle, 라벨 스무딩 0.1, 15 epoch, 입력 224, 검증 15% 분리 후 검증 정확도가 가장 높은 epoch 선택
- 변환: PyTorch → LiteRT(TFLite) → 사후 양자화(INT8, 보정 200장)

## 한계

- 검수는 한 번만, 썸네일 크기로 진행했습니다. 애호박과 오이처럼 구분이 어려운 사진은 오판이 있을 수 있습니다.
- 틀린 94장은 모델의 예측을 본 상태에서 검수했습니다. 새 모델에 유리하게 기울었을 가능성이 있습니다.
- Open Images 학습 분할에도 같은 라벨 오류(라임→레몬, 애호박→오이)가 있을 것으로 보이며, 학습 데이터는 아직 정제하지 않았습니다.
- 테스트셋과 추가 학습 데이터가 같은 출처(Open Images)입니다. 실제 사용 환경의 성능은 직접 촬영한 사진으로 다시 재야 합니다.
- 새 모델은 입력 크기(224)와 구조가 기존 모델과 달라 앱(ML Kit 커스텀 분류기)에서 그대로 동작하는지 확인하지 않았습니다.
- 스마트폰 등 실기기에서의 지연 시간과 메모리는 측정하지 않았습니다.

## 평가 스크립트 실행

```bash
pip install litert-quantizer ai-edge-litert pillow numpy
python benchmark/recipic_benchmark.py --model model.tflite --data ./dataset
```

`./dataset` 아래에 `train/<클래스>/`, `test/<클래스>/` 폴더가 있어야 합니다. `train`은 양자화 보정과 중복 제거에 쓰입니다.
